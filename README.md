# hermetic

A standard library prelude that makes OCaml code take Eio's capabilities as
arguments.

In a file that opens `Hermetic`, a standard library, `Unix` or `Thread`
value that reaches the file system, a clock or the network on its own is a
type error. So is one that reaches the standard streams, the system's
entropy, a new domain or a child process. The error comes with an alert that
names the `Eio.Stdenv` capability to take instead. A library written this
way reaches these resources only through what it is handed. A test can hand
it a mock clock, an in-memory file system or a recorded network. A reviewer
can read what the library may touch from its arguments.

The prelude guards against accidents, such as an `open_in` or a
`print_endline` written out of habit. It does not stop an author who wants
to cheat, since `Hermetic.Stdlib_original` and `external` declarations stay
available.

## Installation

<!-- $MDX skip -->
```sh
$ opam install hermetic
```

`hermetic` does not depend on Eio.

## Usage

Add `hermetic` to the library's dependencies:

<!-- $MDX skip -->
```
(library
 (name model)
 (libraries hermetic))
```

Then open the prelude on the first line of each source file. A call to
`open_in` no longer builds:

```ocaml
# open! Hermetic;;
# let load () = open_in "model.bin";;
Line 1, characters 15-22:
Alert ambient: Hermetic.open_in
Opens a file by name: take Eio.Stdenv.fs or Eio.Stdenv.cwd (an Eio.Path) as an argument, or the file's contents.

Line 1, characters 15-22:
Error: This expression has type ambient
       This is not a function; it cannot be applied.
```

A refused value keeps its name but gets one of three abstract types. The
type `ambient` marks a value that reaches an Eio capability without being
handed it. The type `unsafe` marks a value that can forge memory or a value
of any type. The type `unreviewed` marks a value this version of `hermetic`
has not reviewed yet. Nothing in the prelude consumes these types, so using
such a value is an error in every build profile. Silencing the alert hides
the message but not the error.

A few rules make this work:

- Write `open!`. A plain `open` raises warning 33 when the file uses
  nothing from the prelude, and warning 44, under `-w +a`, when it shadows a
  standard library name.
- Put the open on the first line. Code above it is outside the prelude.
- Give each source file an interface. An interface does not open the
  prelude, so it names the standard library's own types, and a consumer of
  the library needs nothing from `hermetic`.
- Keep lexers and parsers generated by `ocamllex`, `ocamlyacc` or `menhir`
  in a library of their own. The code they generate calls `Lexing.engine`,
  `Parsing.yyparse` or `Obj.magic`, which the prelude refuses.

### Applying it to a whole library

A compiler flag opens the prelude in every file of a library:

<!-- $MDX skip -->
```
(library
 (name model)
 (libraries hermetic)
 (flags (:standard -open Hermetic)))
```

The flag also opens it in the interfaces. A type an interface then names
through a module the prelude restates, such as `Digest.t`, is the prelude's,
and the library's consumers need `hermetic` in their path. This is why the
`open!` at the top of each file is the recommended setup.

A library can also ship without `hermetic` and be checked in a separate
directory. There, a library stanza compiles a copy of each source file with
the flag. `copy_files#` keeps the line directives, so errors point at the
original files:

<!-- $MDX skip -->
```
(copy_files# (files ../lib/*.ml))

(library
 (name model_hermetic)
 (libraries hermetic)
 (flags (:standard -open Hermetic)))
```

### Unix and threads

The prelude restates `Unix`, `UnixLabels` and `Thread` as well, but
`hermetic` does not depend on the unix and threads libraries. A library that
uses them lists them before `hermetic`, as in `(libraries unix hermetic)`.
With `hermetic` first, the link fails with `Error: Wrong link order`.

## Escaping the prelude

`Hermetic.Stdlib_original` is the standard library without refusals. Use it
only where you have checked the call:

```ocaml
open! Hermetic

let get b i = Stdlib_original.Bytes.unsafe_get b i
```

`grep Stdlib_original` finds every such use, unless a module alias such as
`module S = Stdlib_original` hides the uses that follow it.

## What it refuses

The prelude refuses values by the capability they reach, and keeps
everything that works on what the code is handed.

- **File system.** Opening a file by name (`open_in`, `open_out` and the
  openers of `In_channel` and `Out_channel`), the file functions of `Sys`
  and `Unix`, the current directory and temporary files are refused.
  Reading and writing a channel the code is handed still works.
- **Clock.** `Unix.time`, `Unix.gettimeofday`, `Unix.sleep`, the timers,
  `Thread.delay` and the waits with a timeout are refused. The processor
  time, `Sys.time`, stays.
- **Network.** `Unix.socket`, `bind`, `connect`, `listen` and the name
  resolvers are refused. I/O on a socket the code is handed stays, and so
  does `accept` on a listening socket it is handed.
- **Standard streams.** `stdin`, `stdout`, `stderr`, `print_*`, `read_*`,
  `Printf.printf`, the standard formatters of `Format` and `Printexc.print`
  are refused, and so is `Arg.parse`, which prints its usage message and can
  exit. A formatter, a buffer or a channel the code is handed stays.
- **Entropy.** `Random.self_init` and `Random.State.make_self_init` are
  refused. `Hashtbl.create` and the other `create` functions that take
  `?random` lose that argument, and every table is made with
  `~random:false`. Passing `~random` is then a type error with no alert.
- **Domains and processes.** `Domain.spawn`, `Sys.command` and the `Unix`
  functions that spawn, wait for or signal a process are refused.
  `Thread.create` stays.
- **Values that forge capabilities.** `Obj`, the readers of `Marshal` and
  `input_value`, the `unsafe_` accessors, `Lexing.engine` and the internals
  of `Parsing` are refused as `unsafe`. The writers of `Marshal` stay.
- **Libraries declared empty.** Some libraries reach the system past Eio's
  capabilities. The prelude declares their modules empty, so their values
  are unbound. They include `Eio_main`, `Eio_unix` and Eio's backends,
  `Mtime_clock`, `Ptime_clock`, `Fmt_tty`, `Dynlink` and `Runtime_events`.
  Some units of Base and ocamlformat that re-export the standard library
  without refusals are declared empty as well.

The generated documentation of the `Hermetic` module (`dune build @doc`)
gives each refused value with its message.
[test/refusals/hermetic.txt](test/refusals/hermetic.txt) lists every
refusal, one per line.

## Supported compilers

`hermetic` supports OCaml 5.3, 5.4 and 5.5. The prelude is generated at
build time from the installed compiler's standard library and a policy that
names every value it has reviewed. The upper bound moves only after a review
of each new compiler, because until then its new values are refused as
`unreviewed`.

## Limits

- The prelude restates the compiler's libraries only. A dependency that
  writes on the standard output in its own code, as `Fmt.pr` does, is not
  caught. `Base` re-exports `Obj.magic` and other refused values, and the
  prelude cannot declare `Base` itself empty.
- Mutable globals stay. A top-level reference can hold a capability the
  code was handed, and a function that reads it later uses that capability
  without taking it as an argument.
- The process environment (`Sys.getenv`), the command line (`Sys.argv`),
  `exit` and the signals stay. Eio's env does not provide them, so there is
  no capability to take instead.
- Nothing checks that a file opens the prelude.

## Related work

Eio's
[design note on capabilities](https://github.com/ocaml-multicore/eio#design-note-capabilities)
describes the gap the prelude fills: "Since OCaml is not a capability
language, code can ignore Eio and use the non-capability APIs directly."
[Emily](https://cs.pomona.edu/~rbull/emily/) is a capability-secure subset
of OCaml checked by a verifier. `hermetic` uses the stock compiler and keeps
mutable globals. [Joe-E](https://people.eecs.berkeley.edu/~daw/papers/joe-e-ndss10.pdf)
does the same for Java, and [cap-std](https://github.com/bytecodealliance/cap-std)
is a capability-based standard library for Rust.
